TASK FOR AI AGENT: Implement "get_toolbox_asset" action in NEXUS AI

CONTEXT
-------
This is a Next.js + Convex project called NEXUS AI (Roblox Studio AI
assistant). The AI model can emit JSON "action" commands inside chat
responses (e.g. create_instance, read_script, edit_script, etc).
These actions are parsed in the frontend chat file and either:
  (a) sent to the Roblox Studio plugin via Convex HTTP, or
  (b) executed directly against a backend service (no Studio needed).

IMPORTANT PIVOT — READ THIS FIRST
----------------------------------
An earlier version of this task targeted Roblox's keyword-SEARCH
endpoint (`/toolbox-service/v2/assets:search?query=coin`). That
endpoint returned HTTP 403 "Scope not authorized" because it is an
internal endpoint used only by Roblox Studio's own Toolbox UI — normal
Open Cloud API keys (created via Creator Dashboard) are not granted
that scope, and there is no dashboard setting that unlocks it.

The endpoint that IS officially documented and supported by a normal
Open Cloud API key is "Get Creator Store Asset Details":

  GET https://apis.roblox.com/toolbox-service/v2/assets/{id}

This means: the AI CANNOT search the Toolbox by keyword anymore. It
can only fetch details for an asset ID that is already known (typed by
the user, found elsewhere in chat history, or returned by a prior
insert_asset call). The action has been renamed accordingly from
"search_toolbox" to "get_toolbox_asset" to avoid confusion — if any
earlier partial implementation used the name "search_toolbox", rename
it to "get_toolbox_asset" everywhere (action name, function names,
chip label, system prompt docs).

GOAL
----
Add an action called "get_toolbox_asset" that lets the AI fetch details
(name, type, creator, vote stats, thumbnail) for a single Roblox asset
by its numeric ID, using Roblox's official Open Cloud endpoint above.

This action does NOT need the Roblox Studio plugin to be connected.
It is a pure server-side fetch using the existing environment variable
ROBLOX_OPEN_CLOUD_KEY (already configured in Convex env).

Backend files "ts/toolbox-service.ts" and "ts/toolbox-http.ts" have
ALREADY been created/rewritten for this endpoint (see attached files
in this delivery, or recreate them exactly as specified in STEP 0 below
if missing). Your job is to wire the rest of the system around them.

STEP 5 — Frontend: handle the action inside autoInjectToStudio()
==================================================================
Same file, inside the function autoInjectToStudio(). This function
loops over parsed action commands and normally sends each one to the
Studio plugin via _injectCommand(). The get_toolbox_asset action must
be intercepted BEFORE that network call, because it doesn't need
Studio at all.

Inside the for-loop, right after this existing line:

Insert this new block:

  if (a === 'get_toolbox_asset') {
    updateStep(step.sid, 'info', undefined, 'Looking up asset on Roblox Toolbox...')
    const assetId = String(cmd.assetId || cmd.id || cmd.name || cmd.target || '')
    const lookupRes = await fetchToolboxAssetDetails(assetId)
    if (lookupRes.ok && lookupRes.result) {
      const r = lookupRes.result as { name?: string }
      updateStep(step.sid, 'done', `Found asset: ${r.name || assetId}`)
      readResults.push({
        name: `toolbox_asset:${assetId}`,
        source: JSON.stringify(lookupRes.result, null, 2),
        class: 'ToolboxAsset',
        lineCount: 1,
      })
    } else {
      updateStep(step.sid, 'info', undefined, lookupRes.error || 'Asset not found.')
    }
    doneCount++
    continue
  }

IMPORTANT: this block must come BEFORE the existing line:
  const res=await _injectCommand(cmd,user,sig)
...and must `continue` the loop so get_toolbox_asset is never sent to
the Studio plugin. Do not alter the existing logic for any other
action type — only insert this new conditional branch.

Note: this reuses the existing `readResults` array (already typed as
{name,source,class,lineCount}[]) so the JSON result automatically
renders to the user as a code block in chat, exactly like read_script
